# cspub 发布与版本维护

> 本文档是发布流程的唯一规范；README 的「版本维护」一节只留指针。
> 版本规则沿用 cjh：重大更新递增中间位（v0.1→v0.2），小更新递增末位（v0.1.0→v0.1.1）。

## 版本号单一真相

- `cjpm.toml` 的 `version` 字段是唯一版本来源；README / CHANGELOG / tag / release 均以它为准。
- 发版前核对：`grep '^version' cjpm.toml` 与 `CHANGELOG.md` 顶部条目一致。

## 发版门禁（全部通过才可发）

1. `cjpm build` 通过且**编译零警告**（核对命令见 AGENTS.md）；
2. `cjpm test` 全绿（行为变更必须有对应测试）；
3. 端到端凭证：真机 `publish`（草稿）回显 article id + `imgs` 预演 + 图床直链 `curl` 返回 `200 + 非零字节`；
4. `CHANGELOG.md` 已更新本版本条目（每条带验证证据）。

## 发布流程（六步）

```bash
# 1) 构建
cjpm build
# 产物：target/release/bin/main

# 2) 产物入 dist/（命名：cspub-v<版本>-linux-x64）
mkdir -p dist
cp target/release/bin/main dist/cspub-v0.1.0-linux-x64
cd dist && tar czf cspub-v0.1.0-linux-x64.tar.gz cspub-v0.1.0-linux-x64 && cd ..

# 3) 生成校验清单
cd dist && sha256sum cspub-v0.1.0-linux-x64 cspub-v0.1.0-linux-x64.tar.gz > SHA256SUMS && cd ..
sha256sum -c dist/SHA256SUMS          # 必须逐项 OK

# 4) 冒烟：产物可直接运行（补 LD_LIBRARY_PATH 时见 docs/开发文档与踩坑记录.md §6）
./dist/cspub-v0.1.0-linux-x64 help

# 5) 打 tag（格式 v<版本>）
git tag v0.1.0 && git push origin v0.1.0

# 6) 基于 tag 发 release（AtomGit 仓库页 → Releases → 新建，附 dist/ 产物与 SHA256SUMS）
```

## 产物规范

- `dist/` 只放**当前版本**产物：二进制 + tar.gz + `SHA256SUMS`；旧版本产物保留但不再列入清单（沿用 cjh 做法）。
- 命名格式：`cspub-v<版本>-linux-x64[.tar.gz]`；Windows 侧交叉编译未实测，跑通后按 `cspub-v<版本>-windows-x64.exe` 补充。
- `SHA256SUMS` 覆盖当前版本全部产物，发布前 `sha256sum -c` 必须全 OK；用户下载后按同文件校验。

## 版本历史回填规则

- 每次发版，`CHANGELOG.md` 顶部新增对应条目（日期 + 版本号）；未发版的变更记在 `## [Unreleased]`。
- 条目分节：新增 / 变更 / 修复 / 文档 / 构建 / 已知限制；**每条带验证证据**（实测输出、错误码、转存结果），不写没有证据的条目。
